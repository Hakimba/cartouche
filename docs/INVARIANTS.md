# Invariants

Guarantees every change must keep. Each id is part of the name of the test (or tests) enforcing it.
Weakening one is a design decision to discuss first, never a side effect of a change.

| Id | Area | Invariant | Why |
|---|---|---|---|
| INV-E0-01 | Launch | Templates can never grant URI permissions: `--grant-*` and any `-f` value with a grant bit are rejected, and a `LaunchSpec` can only be built by resolving a template (its constructor is internal). | Player definitions are third-party data. |
| INV-E0-02 | Launch | Only the game's own URI is ever granted, exactly when the launch depends on it; no other content URI is handed where Android grants access with the intent (the data URI, `--eu` extras). | A template must not reach other files in a granted folder. |
| INV-E0-03 | Launch | Placeholder values are inserted verbatim in every kind of value, including string arrays. | A file name with quotes, commas or `-n …` must not change the launch. |
| INV-E0-04 | Launch | Parsing and resolving templates is total: a template or a typed error, never an exception. | Bad data is reported, not a crash. |
| INV-E0-05 | Launch | Single- and double-quoted tokens tokenize back to themselves. | The tokenizer never loses or alters characters. |
| INV-E0-06 | Launch | A template needing `{file.path}` never launches a file without a filesystem path. | Otherwise the emulator starts with an empty ROM argument. |
| INV-E0-07 | Catalog | Every definition file shipped in `app/data/platforms` parses with no rejection. | Updating bundled data must not silently lose emulators. |
| INV-E0-08 | Catalog | A broken or duplicate player is rejected alone, a broken or duplicate platform, or one without a Cartouche profile, whole, and every rejection is reported. | Nothing disappears silently. |
| INV-E0-09 | Catalog | Hidden files (`.x`, `._x`) are never offered to a player, whatever the patterns say. | They are not games. |
| INV-E0-10 | Catalog | Catalog parsing and file matching are total. | As INV-E0-04, for definition files and names. |
| INV-E0-11 | Storage | Only documents of the external storage provider map to a filesystem path; the mapping is total. | `{file.path}` must never point to a guessed location. |
| INV-E0-12 | Android | Whatever the template, a launch intent grants read access to the game URI when it hands it, and to nothing else; it never grants write, persistable or prefix access. | The emulator can open the game; nobody can write to ROM folders. |
| INV-E0-13 | Android | Launches always start a new task and keep the template's activity switches. | Templates are written for `am start`. |
| INV-E0-14 | Android | Only read access to a picked folder is kept. | Cartouche never writes to ROM folders. |
| INV-E0-15 | Android | Every folder pick is answered exactly once: by its result, by the failure to open the picker, or as cancelled by a newer pick. | A screen awaiting a pick never hangs or gets two answers. |
| INV-E0-16 | Android | Everything the plugin sends to Godot is a value its JNI bridge converts: text, booleans, numbers, Dictionaries, lists of Dictionaries as `Object[]` and lists of texts as `String[]`. | Any other array, and a String inside an `Object[]`, reaches GDScript as an opaque object. |
| INV-E1-01 | Library | Every file a scan lists ends up in exactly one place: a disc of one game, or the ignored files. Copies and other formats of a game stay separate games. | Nothing disappears or merges silently. |
| INV-E1-02 | Library | A scan does not depend on the order the folder lists its files in. | The same folder always gives the same library. |
| INV-E1-03 | Library | Reading a game name is total, never gives a blank title, and reading a title again gives the same title. | Any file name is shown as something readable. |
| INV-E1-04 | Library | A file is only identified as a reference disc of the same title and edition (not a demo or beta for a retail file) that nothing in its name contradicts (region, languages, version, disc): as that very disc when a single one matches its name exactly, otherwise only by the serials all possible discs share, and not at all if they share none. A game shows the regions, languages and version its file name states. Reference names identify as themselves. | A wrong serial or name is worse than none. |
| INV-E1-05 | Library | A stored library reads back identical. | Restarting the app never changes the library. |
| INV-E1-06 | Library | A rescan keeps what was chosen for games still there, drops games whose files are gone, and changes no other platform. | Rescanning is always safe. |
| INV-E1-07 | Library | Only a file that a player of the platform accepts becomes a game; hidden files and BIOS files never do. | Emulator data and system files are not games. |
| INV-E1-08 | Library | An unreadable library file is set aside, never overwritten. | A bug or a bad write does not destroy the user's library. |
| INV-E1-09 | Library | A scan lists every file of its folder and, with sub-folders on, of its sub-folders, each once, even when the provider lists a folder in two places. A sub-folder it does not look into (hidden, emulator data, 8 or more levels down, or unreadable) is listed with the reason, and never hides anything else. | Nothing disappears silently or shows twice, and one bad folder does not spoil a scan. |
| INV-E1-10 | Library | Without sub-folders, a scan lists the platform's folder only. When that folder cannot be listed, the scan fails. | The choice is honoured, and a removed SD card does not empty the library. |
| INV-E1-11 | Library | A scan ends whatever the documents provider answers, including a folder listed inside itself. | A faulty provider cannot hang the app. |
| INV-E1-12 | Android | Whatever rows a documents provider returns, or however it fails (including a listing cut short), listing a folder gives all its entries or a typed failure, never a crash or a partial listing. | Documents providers are third-party code. |
| INV-E1-13 | Library | The stored library, and the library sent to Godot, grow with games, with files a player opens and with skipped folders (all bounded by the 10,000 entries of a scan), never with hidden or unsupported files: those are only counted, with their first names. | A folder of emulator data or downloads cannot slow the app down. |
| INV-E1-14 | Library | A scan fails past 10,000 entries (files and folders), naming the folder that listed the most, and changes nothing. Cartouche reads at most one entry more from a documents provider, though the provider itself still lists each folder whole. | The worst scan takes seconds, and a partial scan never drops games. |
| INV-E1-15 | Library | A sub-folder named like emulator data (`app/data/scan/data_folders.json`, any case) is reported and never listed. The list holds none of the usual names of game folders (`roms`, `games`, platform ids). | Emulators keep tens of thousands of files next to the games. |
| INV-E2-01 | Shelves | Every platform of the catalog that has games has one shelf, in catalog order, holding exactly its games in title order whatever the order of the library. Each shelf starts on the remembered game, else the one that followed it, else the first; the carousel starts on the remembered platform, else the first. | Coming back always lands somewhere sensible, even after games are gone. |
| INV-E2-02 | Carousel | A game is never shown twice at once, and never hidden within reach: a stopped row shows the selected game in the middle and its consecutive neighbours; a shelf that fits on screen (4 games at most, see `WHOLE_SHELF`) is shown whole, in order, without wrapping around. A game appears or leaves only where it cannot be seen, and never jumps from one end to the other. | A shelf of two or three games must not look like more, or less. |
| INV-E2-03 | Carousel | Each step moves exactly one game along the endless row, whatever the speed: n steps one way then n the other come back to the same game. | No game is ever skipped. |
| INV-E2-04 | Carousel | A held direction repeats faster and faster, never more often than every 48 ms (20 steps a second at 60 fps), and releasing it stops the steps at once. | Fast, but the user always stops where they let go. |
| INV-E2-05 | Shelves | A stored selection reads back the same; an unreadable selection file only means starting from the first game; a rescan keeps the selected game while it is there. | Restarting or rescanning does not lose the user's place. |
| INV-E2-06 | Carousel | Every media of the platforms has a model, and every model loads with a `Label` mesh the carousel can draw on. | Replacing a model is data only, and cannot break a shelf. |
| INV-E2.5-01 | Carousel | Without the Android plugin (editor, desktop), the catalog is the plugin's for the shipped definitions, and the demo library a fresh one with nothing selected, both exactly as the plugin sends them. The Kotlin test is `INV-E2_5-01`, as test names cannot hold a dot. | Models and materials are tuned on a computer, on the shelves the device shows. |
| INV-E2.5-02 | Models | A disc built from any dimensions it accepts is closed, every face turned outwards; it fills exactly its size and nothing comes into its hole; the label covers the top exactly between its radii, a label image covering the whole face upright, and the mirror the bottom, marked recorded only between the data radii. | A disc has no gap or stray face at any size, and a scanned label lands where it is printed. |
| INV-E2.5-03 | Models | A cartridge built from any dimensions it accepts is closed, every face turned outwards, except under its raised plate; it fills exactly its size, its label flat at the bottom of its recess, a label image covering it upright. | The shell has no hole or fold, whatever its notches, bevel and label. |
| INV-E2.5-04 | Models | Impossible dimensions are refused with the reasons and build nothing; every shipped model is built from dimensions that fit, each of its parts with faces. | A wrong number in a model's data is reported, never drawn as a broken model. |
| INV-E2.5-05 | Carousel | Every game shows a label: its image when there is one, else its title, in the ink (dark or white) further from the label's colour, at least 0.43 apart in luminance; on made-up artwork, white ink with an outline. | A game without artwork can still be told apart. |
| INV-E2.5-06 | Carousel | On a stopped row, only the selected game is posed: the games beside it stand as the layout places them, and the pose keeps within its tilt, turn and sway. | The pose never breaks INV-E2-02's layout. |
| INV-E2.5-07 | Carousel | The right stick turns the selected game any way, up to its back; let go, the game stays exactly as it was left, and the games beside it do not move; once another game is selected, the one turned turns back to the front as it leaves, and the one arriving turns from its front. | A game can be looked at from every side, its back included, without holding the stick. |
| INV-E3-01 | Launch | Checking whether a game can launch starts no activity and stops no process, whatever it finds. | The check runs before the insertion plays, and must not end a game left running. |
| INV-E3-02 | Launch | A launch fails exactly as its check did, and goes ahead exactly when its check did; it stops a lingering emulator only when it goes ahead and the definition asks to. | The insertion only plays for a game that starts. |
| INV-E3-03 | Launch | A game whose file is gone, or whose storage cannot be read, never launches; when its emulator is there (or Android picks one), it fails as `game_missing`. Every launch failure reaches the carousel with its own code. | A removed SD card gives a clear message, not an emulator error. |
| INV-E3-04 | Carousel | Whatever a launch comes to (refused at the check or at the start, started then back, back or gone before the start is answered, never left for the emulator, a check or a start never answered), the carousel shows again as it was: the same game selected and where the row places it, the controls shown, no spindle and no black. A started game keeps the screen all black until the user comes back, or for 5 s at most while the launch waits for an answer or for Android to leave for the emulator. A refused launch shows its message; a game that cannot start plays no insertion. | Coming back is always clean, and a failure never leaves the screen black. |
| INV-E3-05 | Carousel | From A until the carousel shows again, no input acts, not even one begun before A (a held direction, the stick, Select): the selection and the shelf do not change, and no second launch starts. | Buttons pressed during the insertion or the game cannot launch another game. |
| INV-E3-06 | Android | There is never more than one curtain, and every one comes down: after its time (10 s at most, longer times are refused), as soon as Cartouche is back, or at once if the start it covers fails; without the permission, or with a time of zero, none is raised. Lowering it when Cartouche is back is the plugin's, checked on a device. | A black screen can never stay over the emulator. |
| INV-E3-07 | Carousel | An insertion starts where the game stood, never moves faster than its steps take it, and ends seated on the spindle, facing the drive; the drive spins the game from its seating only, never backwards, and only with a spindle; the black grows from nothing to the whole screen once the game is seated. | The motion reads as putting a disc in a drive, whatever its timings. |
| INV-E3-08 | Carousel | Every medium has an insertion lasting at most 1.8 s. | The check and the start keep 0.2 s of the 2 s from A to the emulator. |
| INV-E4-01 | Art | A game only ever gets scans of its own disc: those of the one game its title names in the art extract (fan-made images are not in it), closest to its regions first (its own region, its group's umbrella, the rest of its group, the world, then NTSC-U, PAL, NTSC-J), equally close ones in the extract's order; then those its platform's serial source names after its own serials. Never a box cover. | A label is always the right game's real disc, as close as possible to the user's copy. |
| INV-E4-02 | Art | A title finds its game whatever its case, accents, punctuation and spaces, by the game's name before its alternate names (a name of no Latin letter, such as a Japanese one, is found by its romanised alternates); a title that names several games, with scans or not, gets none of their scans. | A near miss in a name still finds the art; an ambiguous one never shows another game's. |
| INV-E4-03 | Art | Whatever the network, the servers and the app do (stops, starts, scans, stalls, retries), a game is looked for by one request at a time, its image downloaded once at most, never looked for again once found, and a resumed run asks for exactly what is left. | Scraping is resumable and never downloads twice. |
| INV-E4-04 | Art | Only whole images are taken for stored ones: an interrupted or failed write leaves no image. | A cut during a download never shows a broken label. |
| INV-E4-05 | Art | A network or server failure never makes a game give up: it is tried again, after a delay that doubles from 30 s to 15 min, or as soon as the network is back; only a game none of the sources has is remembered as without art, until the sources change. | Being offline or over a quota costs nothing: the art comes later. |
| INV-E4-06 | Art | Stored images are found without the network, whatever it does, and looking for the others never waits for it. | The carousel shows what it has at once, offline too. |
| INV-E4-07 | Carousel | A scan that arrives replaces the title drawn on its game in view, and nothing else: the other games keep their labels, every game its place, the selection stays. | Labels appear as they come, without moving the carousel. |
| INV-E5-01 | Carousel | The right stick turns the selected console on the consoles screen only: never while going in or out, on the games screen, or during a launch; going in turns it back to the front. | The console is looked at where it is chosen, and stands as its animation has it everywhere else. |
| INV-E5-02 | Carousel | The right stick turns the selected game on the games screen only (INV-E2.5-07 there); a game turned then launched still leaves from where it stood and ends on the spindle. | A disc is looked at where it is chosen, and goes in whatever way it was turned. |
| INV-E5-03 | Carousel | A launch animation made from steps reaches each step exactly and holds it until the next leaves; between two steps each value follows the step's curve (the cubic ones exactly, the rebound within a tenth of the way beyond); before its start and after its end it holds its first and last step; its moments (consoles, games, launch, seated, black) fall where its steps have them. Put into its console, the disc leaves from where it stood. | What was tuned in the animation's steps is what plays, and nothing jumps. |
| INV-E5-04 | Carousel | Going into a console then back out leaves the consoles screen exactly as it was (same console, standing as its animation starts), and the games screen finds the game it was left on. | Going in and out is free to try. |
| INV-E5-05 | Carousel | While the console opens or closes, nothing pressed acts: neither console nor game changes, no launch starts, Select does not open the device check. | A press during the animation cannot go somewhere else than where it leads. |
| INV-E5-06 | Carousel | The carousel opens on the consoles screen, on the remembered console, still; back from a game, it is on the games screen as it was left (INV-E3-04). | Opening Cartouche starts from the consoles, and a game ends where it started. |
| INV-E5-07 | Models | A console built from any dimensions it accepts is closed part by part, every face turned outwards; the lid's opening goes through its top down to the well, the lid fills it but for its gap, turning about its back edge so that its front rises; a seated disc's centre is over the well's centre, at its seat height, its axis up. Impossible dimensions are refused with the rules they break and build nothing. | The console has no hole or stray face at any size, and a disc lands where the lid closes over it. |
| INV-E5-08 | Launch | Every console with a launch animation takes a game from the games screen to the whole screen black in 2.4 s at most. | With the check and the start, a PS2 game starts less than 2.6 s after A. |
